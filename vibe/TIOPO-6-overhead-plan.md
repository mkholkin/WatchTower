# MB и суммарные затраты диагностики

Перевести отображение памяти ЛР №6 в MB (1 000 000 байт) и добавить дашборд «Суммарный overhead». Использовать сохранённые измерения; новые нагрузочные опыты не запускать. Текущий набор данных Grafana сохраняется.

1. Рассчитать по каждому профилю/режиму/повторению CPU всего стека и внешних средств диагностики, среднюю по времени суммарную память, а также разницу всего стека с matched baseline. Стек: API, Docker-сборщик, OTel Collector, Tempo. Память суммировать по средним за одно окно, не по медианам. Добавить OpenMetrics и тесты границ/формул.
2. Добавить вкладку-дашборд с абсолютными затратами, разницей к baseline, RPS и ошибками. Сохранить фиксированное окно summary-запросов и реальные проверки через Grafana query API. Перевести существующие панели, отчёты, графики и численные таблицы ЛР №6 из MiB в MB; исходные байты оставить неизменными.
3. Проверить unit-тесты и расчёт на сохранённых локальных/CI-данных, обновить текущий стенд без смены набора данных, проверить все панели реальными instant-запросами с нулевым диапазоном. Обновить методику и опубликовать изменения в связанных ветках.

Формулы: CPU стека = сумма CPU четырёх процессов; CPU внешних средств = сумма трёх процессов без API; дополнительный расход = значение всего стека минус baseline того же профиля и повторения. Для памяти используются средние по времени working set за одинаковое окно. Отрицательную разницу сохранять; RPS и ошибки показывать рядом.
