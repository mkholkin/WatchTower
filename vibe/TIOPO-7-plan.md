# ЛР №7: статический анализ Go

Задача: проверить всю собственную Go-кодовую базу, включая тесты, по цикломатической сложности ≤10, вычислять метрики Холстеда, проверять gofmt и go vet. Одни и те же проверки должны блокировать обычный коммит и выполняться в CI перед тестами. Сгенерированный код исключается только из метрик по стандартному заголовку генератора; сторонние зависимости и артефакты не входят в собственный исходный код.

1. Добавить `tools/lab7/metrics`: отдельный Go-модуль с закреплёнными gocyclo v0.6.0 и maintidx v1.0.0, JSON-отчётом на каждую функцию/замыкание и отказом при CC>10. Проверить границы 10/11, формулы Холстеда, ошибки разбора и область анализа командой `go test ./...` внутри модуля.
2. Выполнить рефакторинг существующих функций без изменения поведения: CLI/бенчмарки, репозитории, HTTP-обработчики, запуск приложения, сервисы и тесты. Проверить метриками и тестами затронутых Go-пакетов. Исключения и подавления для собственных функций не добавлять.
3. Добавить общий `tools/lab7/check.py`, проверку gofmt/go vet и метрик, `.githooks/pre-commit`, установщик hooksPath, Makefile и общий CI-job перед тестами всех лабораторных. Hook проверяет снимок индекса Git, чтобы незакоммиченные исправления не скрывали ошибки staged-кода. Проверить успешный коммит, блокировку плохого форматирования/CC11/ошибки типов и обход через `--no-verify` в одноразовом репозитории.
4. Сохранить фактический JSON-отчёт, короткий отчёт выполнения и таблицу «требование → файл/команда» в `tiopo/lab7`. Выполнить `make lab7-check`, общий статический gate и полный набор собственных Go-тестов, затем закоммитить результат в `TIOPO-7`.

Метрики Холстеда информационные: условие не задаёт для них численного порога. Собственные проверки не запускают тесты проекта; в CI тесты следуют только после успешного статического job.
