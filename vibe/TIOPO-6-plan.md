# ЛР №6: трассировка и стоимость наблюдаемости

1. Добавить отключаемые HTTP/pgx spans с корреляцией и безопасным JSONL-экспортом; расширенные HTTP-логи на debug. Проверить связи, длительности и отсутствие секретов.
2. Повторить неизменные пять профилей ЛР4 в матрице tracing on/off × info/debug. Сохранить ресурсы всех контейнеров, traces, логи, параметры и очистить стенд после каждого опыта.
3. Рассчитать CPU-seconds, min/median/max RAM, задержки/RPS/ошибки и накладные расходы относительно baseline. Отдельно измерить сборщик ресурсов.
4. Проверить smoke, выполнить полную матрицу; сохранить сравнение и выводы, Allure и таблицу требований; настроить CI, проверить diff и закоммитить в TIOPO-6.

Используется собственный in-process JSONL tracer: задание допускает любое средство. Экспорт синхронный, поэтому его стоимость входит в ресурсные метрики API; отдельного collector трассировки нет. По trace ID связываются HTTP spans и PostgreSQL spans. Для просмотра отчёт конвертирует spans в Chrome Trace Event JSON.
