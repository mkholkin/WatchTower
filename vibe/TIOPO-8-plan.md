# ЛР №8: внешняя RDAP-интеграция

WatchTower получает регистрационные сведения о домене HTTP-монитора через публичный RDAP API Verisign. Контракт: RFC 9082/9083 и документация Verisign; область реализации — домены `.com`. Адрес RDAP и таймаут задаются конфигурацией, что переключает приложение между mock и реальным сервисом.

1. Добавить `internal/infra/rdap`, настройки `configs.RDAP`, защищённый HTTP endpoint `/monitors/{monitorId}/registration` и `api/rdap.openapi.yaml`. Проверить права владельца, границы внешнего контракта, таймауты и ответы внешнего сервиса. Все собственные Go-функции сохраняют CC ≤10; выполнить `make lint` и тесты новых пакетов.
2. Добавить mock-сервер, контрактные фикстуры и E2E `tools/lab8/e2e.py`: регистрация, вход, создание монитора, получение RDAP. В mock проверить успешный ответ, ошибки, отсутствие даты и отказ до upstream для чужого монитора. Реальный E2E делает один RDAP-запрос для `example.com`; даты проверяются по схеме.
3. Добавить `tools/lab8/run.py`, Compose и команды Makefile для E2E, демонстрации mock/real и остановки. Расширить сценарий ЛР4 опциональным RDAP-запросом; основной профиль `soak-0` остаётся 15 с прогрева + 300 с при 4 VU. Сохранить raw k6, метрики контейнеров, статистику mock, Allure и отчёт.
4. В CI после статического gate запускать E2E с mock, полный фиксированный нагрузочный тест с mock и E2E с реальным API. Сохранить артефакты при ошибках. Выполнить локальный smoke, полный прогон и демонстрацию обоих режимов; сохранить результаты и таблицу «требование → файл/команда» в `tiopo/lab8`; закоммитить и отправить ветку `TIOPO-8`.

Реальный API используется для единичного E2E и демонстрации; нагрузка направляется только на mock согласно условиям Verisign. Выбор внешнего сервиса согласуется студентом с преподавателем.
