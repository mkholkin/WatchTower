# Результаты ЛР №2

Проверка выполнена 29 сентября 2026 года локально из ветки `TIOPO-2` на macOS/Apple Silicon. Для стенда создан отдельный профиль Colima `watchtower-lab2` с 2 CPU, 4 ГиБ RAM и диском 30 ГиБ: диск уже работавшей Docker VM был заполнен. Существующие контейнеры и тома не удалялись, глобальный Docker-контекст не переключался.

Команды этой проверки используют `DOCKER_CONTEXT=colima-watchtower-lab2`. На другом компьютере с работающим Docker эта переменная не нужна. Локальный профиль можно запустить командой:

```sh
colima start watchtower-lab2 --vm-type vz --cpu 2 --memory 4 --disk 30 --activate=false --ssh-config=false --mount "$PWD:w"
DOCKER_CONTEXT=colima-watchtower-lab2 make lab2
```

## Обнаруженные дефекты

Первый реальный прогон `initial-real` прошёл модульные тесты и остановился на интеграционном сценарии общей цели: после отключения быстрого монитора интервал остался 10 секунд вместо 30. E2E был пропущен, Allure сформирован, таблицы и Redis очищены. Исправлен пересчёт цели: учитываются только активные мониторы.

В прогоне `service-fixed` все шесть интеграционных сценариев прошли. E2E обнаружил HTTP 500 при запросе `/monitors` без авторизации. Общий преобразователь ошибок учитывал только обёртку `service.Error`, пропуская обычные ошибки сервиса. Теперь он проверяет цепочку ошибки через `errors.Is`, возвращает 401 для отсутствующей авторизации и 404 для отсутствующего ресурса, включая `repo.ErrNotFound`. Добавлены проверки преобразования ошибок и реального HTTP-маршрута.

SQL-воспроизведение `disable-repro.log` подтвердило нарушение уникальности `monitor_status_log(monitor_id, start_time)` при отключении монитора после `UP`. Запрос отключения теперь обновляет время статуса строго после предыдущего значения. SQLC-код пересоздан генератором версии 1.30.0. Интеграционный сценарий дополнен проверкой двух смежных интервалов истории.

## Проверки инфраструктуры

`python3 -m unittest tools/lab2/test_run.py` — четыре проверки прошли: чистый checkout, допустимые идентификаторы, отчёт при ошибке подготовки, порядок завершения при SIGINT/SIGTERM. Скрипт Bash проходит синтаксическую проверку.

Прогон `setup-failure` с намеренно отсутствующим образом завершился с кодом 1. Сохранены настоящий Allure HTML, запись истории, `setup: failed` и три пропущенных этапа. Для генерации использован уже собранный тестовый образ.

`go test ./...` после исправлений завершился успешно. Полный вывод находится в `build/lab2/work/native-go-test-final.log`.

## Успешные прогоны

`verified-repeat` завершился с кодом 0: 425 модульных случаев, шесть интеграционных сценариев по два раза, один HTTP E2E и его повтор через curl. В исходных данных Allure 442 успешных результата; HTML показывает 436 случаев с учётом четырёх маркеров этапов и объединяет повторные интеграционные сценарии как шесть повторов. `traffic.pcap` содержит 30 143 байта реального трафика, текстовая расшифровка сохранена рядом.

`parallel-a` и `parallel-b` одновременно выполнили полный конвейер и завершились с кодом 0. Интервалы выполнения unit пересекаются; у каждого запуска отдельные контейнеры и собственные артефакты. В обоих `cleanup.json` все девять счётчиков таблиц и число ключей Redis равны нулю.

Заключительный `DOCKER_CONTEXT=colima-watchtower-lab2 LAB2_RUN_ID=final-clean make lab2` прошёл с автоматической сборкой собственного образа. Все 436 записей Allure успешны: 425 модульных случаев, шесть интеграционных сценариев, один E2E и четыре маркера этапов. Повтор через curl прошёл, PCAP содержит 30 153 байта. После всех проверок история Allure содержит 11 запусков; тестовых контейнеров не осталось.

Отчёт заключительного запуска: [Allure](../../build/lab2/runs/final-clean/allure-report/index.html). Артефакты находятся в игнорируемом Git каталоге `build/lab2/runs`; они создаются повторным запуском команд и публикуются workflow как CI-артефакты. Итоговая машинная проверка сохранена в `build/lab2/work/verification.json`.

## Ошибки и прерывание

`fail-integration` и `fail-e2e` завершились с ожидаемым кодом 1 после намеренно внесённой ошибки соответствующего этапа. До очистки в PostgreSQL присутствовали контрольные записи; после неё все таблицы пусты и Redis содержит ноль ключей. Allure создан в обоих случаях. После ошибки integration E2E получил статус `skipped`.

`interrupted` получил SIGTERM непосредственно в runner. `launcher-interrupted` получил SIGTERM в скрипт запуска: скрипт завершился с кодом 143, предварительно дождавшись завершающей очистки runner. В обоих случаях integration отмечен как неуспешный с причиной `pipeline interrupted by signal 15`, E2E пропущен, хранилища очищены, Allure сохранён.
