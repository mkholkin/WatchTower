# ЛР №7: статический анализ Go

Работа выполнена для Go-приложения WatchTower, использованного в ЛР №1–6. Проверяются собственные Go-файлы, тесты, бенчмарки и утилиты, включая интеграционные сценарии и отдельный модуль анализатора. Frontend и вспомогательные Python/JS-скрипты не являются объектом Go-анализа.

## Запуск

Нужны Git, Python 3.10+ и Go 1.26+. При первом запуске нужен доступ к Go-модулям; версии анализаторов и контрольные суммы закреплены в `tools/lab7/metrics/go.mod` и `go.sum`.

```sh
make lint
make lab7-check
make install-hooks
```

`make lint` выполняет проверки стиля, метрик и типов без запуска тестов проекта. `make lab7-check` проверяет сам анализатор и реальные Git-коммиты в одноразовом репозитории. Результат последнего статического запуска сохраняется в `build/lab7/metrics.json`; зафиксированный результат этой работы находится в [metrics.json](metrics.json).

`make install-hooks` однократно устанавливает локальный `core.hooksPath=.githooks`. В новых клонах эту команду нужно выполнить снова: Git не активирует hooks из репозитория автоматически. Обычный `git commit` проверяет временный снимок индекса Git, а не рабочую копию. Неподготовленное исправление не скрывает ошибку подготовленного файла; `git commit -a` проверяется по его временному индексу. Ненулевой код любой проверки блокирует коммит.

Явный обход, предусмотренный условием:

```sh
git commit --no-verify -m "reason for bypass"
```

Обход hook не отключает проверки CI.

## Что проверяется

- `gofmt -l`: формат Go-кода; проверка не исправляет файлы автоматически.
- `go vet`: диагностика и проверка типов всех собственных пакетов. Для текущих интеграционных файлов включены `integration,lab2integration,lab2e2e`; тесты при этом не выполняются.
- Цикломатическая сложность: библиотека `github.com/fzipp/gocyclo v0.6.0`, отказ при значении больше 10. База равна 1, решения учитываются по правилам gocyclo. Проверяются именованные функции, методы и анонимные функции. Решения вложенного замыкания также входят в сложность содержащей функции.
- Метрики Холстеда: подсчёт операторов и операндов библиотекой `github.com/yagipy/maintidx v1.0.0`, пакет `halstvol`. Для каждой функции сохраняются `n1`, `n2`, `N1`, `N2`, словарь, длина, объём, трудность и усилие.

Используются формулы `n=n1+n2`, `N=N1+N2`, `V=N*log2(n)`, `D=(n1/2)*(N2/n2)`, `E=D*V`. При отсутствии операндов трудность и усилие равны нулю; неопределённые и бесконечные значения отклоняются. Условие задаёт численный порог только для цикломатической сложности; для метрик Холстеда произвольный порог не вводится. Это синтаксические оценки по соглашениям выбранной библиотеки, а не измерения времени или памяти. Поскольку вложенные функции представлены отдельно и входят в родителя, суммировать их объёмы как независимые части программы нельзя.

Список исходников берётся из Git: tracked и неигнорируемые новые `*.go`. Артефакты, кэши и сторонние `node_modules` не входят в него. Сгенерированные файлы исключаются из метрик по стандартному заголовку `Code generated ... DO NOT EDIT` через `ast.IsGenerated`; список всех 22 исключений сохранён в JSON. Проверки форматирования и типов продолжают охватывать сгенерированные Go-файлы. Подавлений сложности и отдельных исключений для собственных тестов нет.

## CI и результаты

Общий workflow `static-analysis.yml` запускается первым. Тестовые jobs всех workflow ЛР №2–7 зависят от него через `needs: static`. Отчёт метрик публикуется отдельным артефактом с хранением 14 дней. В workflow ЛР №7 после успешного gate выполняются проверки анализатора/hooks и Go-тесты приложения.

[Результаты и проверка регрессий](results.md). [Таблица требований](requirements.md).

## Источники

- [gocyclo](https://github.com/fzipp/gocyclo): правила цикломатической сложности.
- [maintidx v1.0.0, halstvol](https://pkg.go.dev/github.com/yagipy/maintidx@v1.0.0/pkg/halstvol): соглашения подсчёта Холстеда.
- [gofmt](https://pkg.go.dev/cmd/gofmt), [go vet](https://pkg.go.dev/cmd/vet): стандартные инструменты Go.
- [Git hooks](https://git-scm.com/docs/githooks): `pre-commit` и обход `--no-verify`.
