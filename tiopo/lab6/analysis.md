# Выводы по ЛР №6

Полный локальный запуск: `20261110t105253-a41b89`, 10 ноября 2026 года. Выполнены 20 опытов: пять исходных профилей ЛР №4 в четырёх режимах. Получено 195 927 запросов и 351 550 spans в измерительных окнах.

## Условия и проверка данных

Выделенная Colima VM: Linux aarch64, ядро `6.8.0-117-generic`, Docker `29.5.2`, 4 vCPU и 5.77 GiB доступной Docker RAM. API ограничен одним CPU и 768 MiB RAM; генератор и сборщик закреплены за отдельными CPU. Конфигурация и временные окна описаны в [методике](README.md).

Все 20 опытов завершились кодом 0, очистка контейнеров, сетей и томов успешна. Проверки временных рядов, CPU-счётчиков, изоляции ресурсов и присутствия трасс не нашли нарушений. Все четыре режима каждого профиля использовали один собранный API и неизменный сценарий; хэши измеряемых исходников сверены с началом серии. Порядок режимов между профилями менялся.

Для локальной сборки использованы кэшированные runtime и PostgreSQL из ЛР №4 из-за DNS-сбоя Docker Hub в VM; текущий API пересобран без сети. Идентификаторы образов сохранены в manifest.json. В CI предусмотрена обычная сборка с нуля. Коррекция часов VM была временно остановлена на время измерений. Диагностический smoke `20261110t104949-3f0d37` в итоговые цифры не включён.

## CPU приложения

CPU-секунды ниже рассчитаны по приращению сырых счётчиков за измерительное окно. В скобках — разница с baseline того же профиля. Это стоимость процесса API целиком, включая синхронный экспорт spans и запись его логов; отдельного процесса трассировки нет.

| Профиль | Baseline, CPU с | Trace | Debug | Trace + debug |

| ramp | 80.488 | 81.138 (+0.81%) | 82.484 (+2.48%) | 81.000 (+0.64%) |
| stress | 75.968 | 73.967 (-2.63%) | 76.545 (+0.76%) | 75.999 (+0.04%) |
| soak-0 | 75.312 | 75.594 (+0.38%) | 75.281 (-0.04%) | 75.186 (-0.17%) |
| soak-10 | 74.941 | 75.396 (+0.61%) | 75.462 (+0.69%) | 75.862 (+1.23%) |
| soak-20 | 74.967 | 75.172 (+0.27%) | 79.522 (+6.08%) | 75.425 (+0.61%) |

В стабильных профилях трассировка дала наблюдаемую разницу CPU от +0,27% до +0,61%. Расширенные логи — от −0,04% до +6,08%; максимальная разница пришлась на soak-20. Совмещённый режим — от −0,17% до +1,23%. Эффекты не складываются монотонно: единичная серия не позволяет отделить небольшой эффект инструментирования от вариативности выполнения и сборки мусора. Значение +6,08% также требует повторных опытов для причинного вывода.

Во всех 12 стабильных опытах медиана общего RPS равна 36 и неожиданных ответов нет. Ожидаемые 401/400 выделены отдельно. В ramp и stress система насыщается, появляются таймауты и меняется выполненная работа: близкое значение CPU при перегрузке не доказывает одинаковой пропускной способности. Поэтому в [полных таблицах](results.md) рядом с ресурсами приведены RPS и ошибки.

## Память и стоимость мониторинга

Медиана working set API по опытам находится в диапазоне 13.20–17.04 MiB. В [JSON-сводке](measurements.json) и таблицах для каждого режима приведены min/median/max и абсолютная разница с baseline. Знак разницы RAM меняется; один прогон не доказывает экономию памяти или отсутствие утечек. Inactive file cache исключён по правилам ЛР №4.

Сборщик Docker-метрик потребовал от 0.315 до 1.073 CPU-секунды за опыт. Его средняя загрузка — 0.191–0.358% одного ядра; медиана RAM — 8.29–8.31 MiB. Это отдельно измеренная стоимость процесса мониторинга. Она не прибавлялась к CPU API. Ресурсы ОС, гипервизора и Docker daemon являются общими и полностью на конкретный инструмент не распределяются.
