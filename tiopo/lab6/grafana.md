# Grafana, Prometheus и Tempo для ЛР №6

Стенд открывает сохранённые измерения ЛР №6 в Grafana и трассы в Tempo. Полная матрица из 20 опытов выполнена до подключения этого стенда. CPU и RAM API и сборщика получены из исходных Docker-счётчиков; Grafana показывает эти измерения после импорта. Это не новый прогон нагрузки и не свидетельство работы Grafana во время исходных опытов.

## Запуск

Нужны локальный Docker Engine с Unix socket, Docker с Compose, Python 3 и сохранённый каталог полного запуска, указанный в `build/lab6/latest.txt`.

```sh
make lab6-grafana
make lab6-grafana-check
```

Для выбора другого каталога:

```sh
python3 tools/lab6/grafana_stack.py up --run-dir build/lab6/runs/<run-id>
```

Открыть [дашборд ЛР №6](http://localhost:3036/d/lab6-observability). Grafana доступна локально без входа с правами Viewer. Сервисы слушают только loopback: Grafana — порт 3036, Prometheus — 9096, Tempo — 3206, OTLP — 4316. Не публикуйте эти порты наружу.

Остановка:

```sh
make lab6-grafana-down
```

## Импорт измерений

Импортёр читает сырые `resources.jsonl` и сводку `summary.json` выбранного запуска. Из них формируется OpenMetrics, затем `promtool tsdb create-blocks-from openmetrics` создаёт блоки для Prometheus. Исходные временные метки сохраняются; часы опытов не сдвигаются к моменту просмотра. Рабочие файлы стенда находятся в `build/lab6/grafana/<run-id>/`.

Provisioning подключает Prometheus с UID `lab6-prometheus` и Tempo с UID `lab6-tempo`. JSON дашборда хранится в `tools/lab6/grafana/dashboards/lab6.json`; при подготовке рабочей копии импортёр выставляет абсолютный диапазон времени по выбранным артефактам. Если выбрать «последний час» вместо этого диапазона, исторические данные могут исчезнуть с графика.

`lab6_cpu_seconds_total` — накопленный CPU-счётчик контейнера в секундах. График показывает `rate(...[10s]) * 100`: 100% соответствует одному полностью занятому ядру. `lab6_memory_bytes` — working set Docker без inactive file cache; на дашборде байты переведены в MiB. На графике RAM скрываются отсчёты старше пяти секунд, чтобы стандартный lookback Prometheus не продлевал завершённый опыт.

Сводные метрики `lab6_summary_cpu_seconds`, `lab6_summary_memory_bytes`, `lab6_summary_rps`, `lab6_summary_unexpected_ratio` сохраняют значения отчёта за измерительное окно. CPU — приращение счётчика между границами окна, RAM — min/median/max, RPS — медиана, ошибки — доля неожиданных ответов. Ожидаемые ответы 401/400 не приравниваются к неожиданным ошибкам. Сводные панели используют `last_over_time(...[$__range])`: значение видно, когда временная метка сводки попадает в выбранный диапазон. Приближение участка графика не пересчитывает статистику отчёта.

## Чтение дашборда

В фильтрах выбрать запуск, профиль, варианты, повторение и компонент. По умолчанию выбран `soak-0`, все варианты и компонент `api`. Для сравнения стоимости трассировки оставить четыре варианта: `baseline`, `trace`, `debug`, `trace-debug`. Для каждого профиля сравнивать одинаковые повторения.

Первые панели показывают CPU и RAM выбранного компонента и сводку для сравнения вариантов. Панели RPS и ошибок относятся к нагрузке API независимо от выбранного компонента. Панели Collector всегда показывают отдельный процесс сбора Docker-метрик. Его ресурсы не прибавлены к ресурсам API. Для оценки CPU при перегрузке смотреть также на RPS и ошибки: меньший расход CPU может сопровождаться меньшим числом выполненных запросов.

## Просмотр трасс

На дашборде есть ссылка «Tempo — trace lookup», открывающая Explore с источником `lab6-tempo`. Выбрать TraceQL, вставить идентификатор из импортированного `traces.jsonl` и нажать Run query. Пример ID выбранного запуска подставляется в текстовую панель после импорта. Baseline и debug не содержат трасс; для них отсутствие trace ID ожидаемо.

Сохраняются `trace_id`, `span_id`, родитель и историческое время spans. HTTP-операция и вложенные PostgreSQL spans видны внутри одной трассы. Для старых временных меток предпочтителен прямой поиск по trace ID: поиск Tempo по диапазону может не показывать давно завершённые трассы. Пустой результат поиска не заменяет проверку результата импорта.

## Стоимость просмотра

API и collector в исторической матрице измерялись во время нагрузки. Grafana, Prometheus и Tempo измеряются отдельно после импорта: `viewer-resources.jsonl` хранит сырые Docker-счётчики; `viewer-resources.json` в рабочем каталоге содержит сводку CPU в секундах и RAM min/median/max трёх контейнеров за 60 секунд работы стенда. Сохранённая сводка этого измерения — `tiopo/lab6/grafana-resources.json`.

Это стоимость последующего просмотра сохранённых данных. Она не измеряет накладные расходы live-экспорта трасс в Tempo под исходной нагрузкой. Сравнивать её напрямую с CPU API в опытах или прибавлять к нему без общего измерительного окна нельзя. Общие ресурсы Docker daemon, ОС и VM полностью по контейнерам не распределяются.
